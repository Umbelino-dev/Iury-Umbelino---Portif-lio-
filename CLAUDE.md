# Iury Umbelino — Portfolio

Personal portfolio. Tagline: **"Curiosity builds what comes next."** / **"A curiosidade constrói o que vem a seguir."** (per locale, `messages → hero.tagline`).
Edited like an independent one-author magazine: each section opens with a typographic thesis, shows real evidence, closes with a question.

- **Design source of truth:** Claude Design project "Iury Umbelino — Direção Criativa R01" (https://claude.ai/artifact/8pT6pxPLwinMeP1UBA8UnM). Pages: *Direção Criativa R01* (tokens, type, rules), *Homepage R02* (sections, copy, interactions), *Case Study R01* + *Mobile R01*, *Cat Journey R03* (cat state machine; supersedes *Cat States R02*). When the design and this file disagree on a token, Direção Criativa R01 wins.
- **Content sources of truth:** Iury's CV and the portfolio audit (Claude Docs). Typed in `src/content/`.
- **Redesign R2 + R3 (2026-11-09/10)** override the design on: display face (now **Satoshi**), the hero (lettered name mark), the removed Night→Day screen, the cat rail and state machine, the dot cursor, the bilingual tagline and the section markers. See NOTES.md.
- Progress and open questions live in `NOTES.md`, not here.

## Hard rule — no fabrication
Never invent achievements, metrics, test results, clients, testimonials, dates, roles or contact details. The design's copy is mostly placeholder. A fact without a source stays `undefined` and the UI omits it; data copied from the design carries `confirmed: false`. Never present unshipped work as shipped.

## Stack
- Next.js 16 App Router, React 19, TypeScript strict (`noUncheckedIndexedAccess`), `src/`, `@/*` alias.
- **Static export** (`output: "export"`) → Cloudflare Workers static assets (`wrangler.jsonc`, `./out`). No middleware, route handlers that need a runtime, server actions, ISR or image optimisation. `/` → `/pt` via `public/_redirects` (+ meta-refresh fallback in `src/app/page.tsx`).
- Tailwind CSS v4, CSS-first: all tokens in `src/app/globals.css` `@theme`. No `tailwind.config`.
- GSAP + ScrollTrigger + `@gsap/react` only (no second motion library). Import from `@/lib/gsap`, never from `gsap` directly.
- next-intl 4: locales `pt` (default) and `en`, `localePrefix: "always"`. Every page/layout under `[locale]` calls `hasLocale` + `setRequestLocale` and exports `generateStaticParams`. UI strings in `messages/{pt,en}.json` (pt is the type source); facts in `src/content/*` with `Localized<T>` fields. **No `next-intl/plugin`:** `next.config.ts` sets the `next-intl/config` alias itself (Turbopack + webpack), because the plugin loads `@swc/core` at import and its native loader fails in Cloudflare's build image (ERR_SWC_NATIVE_CACHE, 2026-11-13).
- Fonts self-hosted via `next/font/local` (`src/fonts/*.woff2`): **Satoshi** variable (wght 300–900, display, `font-display`; titles 700, numerals 900), **IBM Plex Sans** 400/400i/500/600 (body, `font-sans`, OFL), **Instrument Serif** italic (`font-serif`, OFL) is loaded but unused on the home (Iury, 2026-11-11: the curved face did not work); annotations (`text-note`: dates, status, captions, field names) are Satoshi Medium in a muted tone. The hero statement is Satoshi. No monospace anywhere.
- **Satoshi licence (ITF Free Font License):** self-hosting on this site and making wordmarks are allowed; modifying the font (subsetting, conversion) and distributing it, including through this **public** repo, are not. So the Satoshi files are never committed (`.gitignore`): `scripts/fonts.mjs` fetches the official package before every build (`npm prebuild`; `--lettering` also fetches the TTF for the lettering script). Never commit, subset or convert them.

## Graphic system (R7: no markers)
Iury, 2026-11-11: no marking patterns (codes like T.01 / E.02 / P.01, numbered labels, rulers, hairline rules, square markers, grids, crop marks, crosshairs). Structure comes from type, scale, space and imagery.
- **Voices:** Satoshi names (titles, projects, roles, actions) and, in Medium + a muted tone, annotates (`text-note`: a date, a status, a caption, a field name, "imagem em breve"). Plex explains (reading text). No monospace, no italic serif, no tracked uppercase eyebrows.
- **Order without numbers:** sequences read through placement and scale (the Approach verbs step down; the career roles climb and grow). If a list is a sequence, let the layout say it.
- **Separation by space, not lines.** Lists are spaced paragraphs; a field name in serif above its value replaces a label + rule.
- **Links and actions:** Satoshi bold with an underline (the one line allowed: a typographic affordance), or the paper/ink block button. Nav active item: full opacity, others 65%.
- **Pictures, not wireframes:** a project without a cover gets a typographic poster (its own name in Satoshi Black, cropped by the frame, `ProjectImage`); case-study slots without media show a tone and one serif line.
- **Allowed accents:** the lime `highlight` (max 2 per viewport), grain + soft light on dark surfaces, the cat, the lettered name. The cat's `SectionRail` stays: it is the cat's prop, not a content marker.
- **Interaction feedback:** hover/focus quiets siblings (opacity) and unrolls details in place (clip-path), never a floating popover. Panels open under what opened them with a clip-path reveal (`DUR.slow`).
- **The one drawn line:** the career path is a single animated line (Iury asked for it). It is the only line on content; it is drawn, not a rule.

## Motion
- Durations: fast 160 (hover/focus), base 320 (states/panels), slow 640 (entrances/reveal). One easing: `--ease-out-soft` `cubic-bezier(0.2,0.7,0.1,1)`.
- Animate only transform, opacity, clip-path, mask. Never layout properties.
- Use `useGSAP` (scoped context, auto-revert) and `gsap.matchMedia()` with `MQ` from `@/lib/gsap`. Kill ScrollTriggers, listeners and observers on unmount.
- Content is present in the server HTML. Entrance start states live in CSS under `.js` (class added by an inline script in `[locale]/layout.tsx`) inside `prefers-reduced-motion: no-preference`, with a 3s CSS failsafe; GSAP then animates with `fromTo` (zero any `y` GSAP would parse from the CSS) and no `clearProps`.
- `prefers-reduced-motion`: no jumps, lerps or breathing; instant swaps or hard cuts. The global reset uses `transition: none` — never a tiny duration (it makes computed styles lag a frame).
- Scroll stages: the element with the tall height must be the sticky element's direct parent.
- Effects always use a block body: `useEffect(() => { … })`. Never return an expression — e.g. `scrollIntoView()` now returns a Promise in Chromium, which React then tries to call as the cleanup and crashes.
- No always-on rAF loops: loops start on interaction and stop on idle or `visibilitychange`. The one exception is GSAP's own ticker while a tween runs.

## The cat
One character. `CatFigure` (SVG, `data-cat` parts) is the only drawing; `CatObserver` is S1 (a button: it opens the assistant); `CatAssistant` owns S2–S5 with the typed FSM in `src/components/cat/states.ts` — transitions only via `send(event)`. Any other "ask the cat" control dispatches `CAT_OPEN`. Answers are scripted in `messages/*.json → assistant` and must only use verified facts; free text matches chip keywords or gets the honest "I'm a scripted prototype" fallback. **Rail vs dock:** from 1440px with a fine pointer (home only), S3 is the R03 rail: `SectionRail` (hairline + section ticks in the right page margin) and the cat hangs on it with its paws, riding the page and climbing back to the 40% reading line (lerp, rAF only while moving); idle → it slides down and curls at the rail base. Below 1440 the margin is narrower than the 44px cat, so S3 is the bottom-right dock (as R03 mobile). The `rail:` Tailwind variant pads anything that sits in that margin. Panel open/close timelines live outside the per-state `gsap.context` (`panelTl`) so a state change cannot kill them mid-way. States: S1 observer (hero slot, head ±10°/eyes ±3px toward pointer, no reaction over text) → S2 jump (420ms arc, hero 60% out of view) → S3 cling (30px right rail, follows the 40% reading line, lerp 0.12) → S4 sleep (4s idle, curls bottom-right: **the curled cat is the closed assistant button**, 56px, `aria-label`) → S5 awaken (panel 360×520 max grows from the cat via clip-path; `role="dialog"`, Esc closes, focus in/out). Mobile: no rail — a bottom-right dock and a bottom sheet. Never opens by itself, never covers copy or nav. Same geometry, graphite body, lime eyes in every state. **Drawing (2026-11-13, Iury):** continuous Bézier shapes (round crown and low cheeks, curved ears with inner ears, a pear-shaped sitting body with haunches, front legs in front of the chest with toes, an S tail, nose, faint whiskers), a rim of light (`objectBoundingBox` gradient stroke, bright on each part's top edge) on head, ears and body only. Idle life in the hero runs on hooks the clips never touch: `tail-wave` (path shape tween), `ear-r` (twitch with some blinks), blink every 4–6 s; the eyes are wide with round pupils, two catchlights and a faint lime glow at rest (Iury preferred the old hover look, 2026-11-13); hover / focus on any cat button brightens `glow` (0.45 → 1) and turns the ears slightly forward (`ear-tilt-l/r`, CSS); the near-pointer pose scales the eyes 1.12. Leg pivots are the shoulders (41,86) / (59,86).
**R3 motion system:** every move is a clip in `src/components/cat/clips.ts` (stretch, walk, run, crouch, airborne, falling, grab, land, settle, wake, greet, tailFlick): pure functions returning GSAP timelines on the `data-cat` parts (incl. the two front legs). In the hero, `CatObserver` scrubs stretch → walk left over the "n" → turn → run to the edge of the "o" → crouch (0–48% of the hero; reverses on scroll back). `CatAssistant` owns the FSM: observer → jump (crouch, airborne, apex clamped under the nav, falling, grab on the rail / land in the dock) → cling → sleep (on the rail: lets go, falls, lands, curls; bounded breathing) → waking (wake + stretch, then `WOKE`) → cling; any awake/asleep state → awaken (the scripted assistant) → sleep. An OPEN during the leap waits for the landing. At Contact the awake cat greets once (wave + the "Ask the cat" hint). The hero counts as left at 50% (`HERO_LEFT_AT`).

## Hero, copy and cursor (Redesign R2)
- **Hero:** the h1 is `<NameMark>`: "Iury / Umbelino" lettered as SVG paths by `scripts/lettering.py` (Satoshi read at wght 900 without instancing, kerning via HarfBuzz, every glyph run through a pathops union) into `src/components/hero/name-paths.ts` (generated, never hand-edit). The y and the b are one outline (`ligature`): Satoshi's y is a V; it is cut where its cross-section equals the b stem width (found by bisection), and a vertical stem of that width runs straight down onto the b's stem axis, so the y reads as a Y-like fork whose foot is the b. y = why, b = build. **u-turn (Iury's reference, 2026-11-13; second pass):** the m's last leg does not stop at the baseline: it turns in a half ring (the stem's width all the way round) and rises into the shared stem, leaving a narrow slit with a round bottom. The slit is the gap the font already leaves between the m and the b (no spacing change: tracking 23.9 / −51.9); the ring's bottom dips by the round-letter overshoot; it belongs to the m glyph and overlaps the stem. **b foot (third pass):** below the ring's centre the shared stem is the ring's own right side, rounded outward; the bowl does not touch it. Its lower curve is carried on (a superellipse fitted to Satoshi's bowl, exponent solved so it meets the real bottom without a step) and cut back to leave an open slit (`SLIT` 22 units) that follows the ring's outer edge and runs straight up beside the stem into the counter; the bowl hangs from the stem's top only, as in Iury's reference. **Paths and entrance (fourth pass):** the b (with its slit and the m's ring) is its own glyph `l2-b`, so it rises in sequence with line 2; the ligature is only the y's V + stem, drawn down by the clip rect and overlapping the b's stem by `OVERLAP` 60 units. Joints are hidden by paint order and real overlap (≥ several px): m (leg cut at the ring's centre) → b (ring reaches 40 units up into the leg) → ligature. A 3-unit overlap showed a hairline at 1×; keep overlaps well above a pixel at the smallest mark size. A first pass that widened the gap (Satoshi's u, re-spaced lines) read as a stretched y and was dropped. The I is raised 14 units to the ascender (the l, the b and the i's dot). U and m stay separate, as in the reference. **Text layer:** the h1 holds the real text over the drawing (`textLayer`, exported by the script: font size in cqw of the mark, each line's box at line-height 1 from the hhea metrics, per-line tracking), transparent, `select-text`, `whitespace-pre` (keeps the space, so a drag copies "Iury Umbelino"), `selection:bg-signal/30`; the SVG is `aria-hidden`, `pointer-events-none`, `select-none`. The viewBox includes every descender and nothing masks the mark. Desktop placement uses the script's `anchors` (% of the mark). Desktop: the name and the intro share one column as wide as the mark, centred horizontally, the name centred vertically above the intro; line 1 and line 2 are flush left (the script splits the gap between the two lines' tracking, `ALIGN_SPLIT`). The name comes first on every width, the positioning line and two links under it ("Conheça a pessoa" → #about, "Fale comigo" → #contact) (no edition line, no index rule). Bottom-right of the first screen (Iury, 2026-11-13): `HeroPortrait` (the real portrait, B&W `grayscale contrast-110`, colour + 1px signal ring + 4px lift on hover; radius 1rem, the second exception to radius 0; links to #about with `tabIndex=-1`, since "Conheça a pessoa" is the keyboard path) and `HeroSocial` (outline icons inlined, no icon library; LinkedIn, GitHub, Instagram and e-mail from `contacts`; opacity 60 → signal on hover). Mobile: name → statement → photo (96px) → intro → icons in a row. Behind it all, `HeroSpotlight` (fine pointer + motion only): a soft light under the pointer that reveals a fine dot grid only inside it (Iury, 2026-11-13; the one grid allowed, as atmosphere, never as structure). One 560px layer moved by transform, the dots held still by the opposite background-position; one rAF per pointer move, no loop (4× CPU: steady 30 fps, no frame > 50 ms). ## Accessibility & performance gates
UX evaluation (heuristic, IA, task walkthroughs) with the fixes it led to: `docs/avaliacao-ux.md` (2026-11-13). Nav label for the hero is "Início" / "Home". On mobile the wordmark gets the glass pill once past the hero, so content never scrolls under bare text. From md up it is bare: `md:bg-none` and `md:backdrop-filter-none` (the dark glass is a background-image and the light glass brightens the backdrop; either left a box behind the name).
Semantic landmarks, one h1 per page, ordered headings; visible focus; hit targets ≥44px; text contrast ≥4.5:1; works with keyboard, touch and reduced motion; no hover-only content (on `(hover: none)` project images sit above titles). Image width/height always set; LCP image prioritised; no layout shift from fonts. Never report Lighthouse/CWV numbers that were not measured.
Paint budget (measured 2026-11-13, headless Chromium): avoid large blur radii (box-shadow > ~40px, `filter: blur`, `backdrop-filter`) on anything big or animated; pre-blur images at build time; animate only transform/opacity on layers (`will-change` during the tween). Profile with a 4× CPU throttle and a devtools.timeline trace (RasterTask totals) before and after.
